# 企业架构规范

日期：2026-11-13。状态：现行。挂号、食材推荐、临床数据仓库、报告解读都按这一份建设和重构。业务规格只写本领域规则，不得再规定另一套分层、持久化、错误码或内部调用。

## 1. 上下文

```text
浏览器 / App
    → 网关（登录、限流、Trace）
        → 智能挂号
        → 食材推荐
        → AI 报告解读
        → 身份服务
三个智能体 --X-Internal-Token--> 临床数据仓库
身份服务 <-- 临床数据仓库只核对接诊人归属
```

| 仓库 | 拥有 | 不拥有 |
| --- | --- | --- |
| `moonligh-platform` | 统一返回、错误码、鉴权、Redis、MQ、网关横切、依赖版本 | 挂号、营养、临床事实、菜谱 |
| `registration-assistant` | 账号、就诊人、号源、问诊、权益、收款 | 病情主表 |
| `nutritionist` | 身高、体重、饮食目标、菜谱、配餐 | 病情主表 |
| `clinical-record` | 临床事实、当前快照、事实版本 | 号源、菜谱、解读正文、支付 |
| `report-interpreter` | 原文解析、白话解读、依据片段 | 病情主表。接入前不得自建病情库 |

业务仓之间不依赖对方的 jar。协作走 HTTP。临床事实只有 `clinical-record` 一个主人。

## 2. 拆分与合并

合并进 `moonligh-platform`，全公司只留一份：统一返回、错误码、Trace、内部令牌，以及 MyBatis 的版本号。

拆开，不合成一个服务：

| 边界 | 落点 |
| --- | --- |
| 临床事实和当前快照 | `clinical-record` |
| 账号、就诊人、号源、问诊、权益、收款 | `registration-assistant`，内部再按服务拆模块 |
| 身高、体重、菜谱、配餐 | `nutritionist` |
| 解读正文 | `report-interpreter` |

每个可运行服务再拆四个包。领域不依赖 Web 和 MyBatis。持久化实现领域端口。

| 包 | 职责 |
| --- | --- |
| `controller` | HTTP 入站。不写 SQL，不开事务 |
| `service` | 用例和事务边界 |
| `domain` | 业务规则和端口 |
| `infrastructure.persistence` | Mapper 接口、XML、端口实现 |

出站调用放在 `infrastructure` 的其它子包。调用失败抛平台 `BusinessException`，不把失败响应解析成空业务对象。

领域规则只依赖本包里的端口。用例可以依赖仓储。只有一个数据库实现时，不为仓储再套一层同名接口。控制器只调用例，不调用仓储。科室缓存、渠道收银台这类适配器留在各自的 `infrastructure` 子包。已发布的 Maven 目录、平台历史包 `com.moonligh.consult`、消息生产组名称保持不变。

不合并这些：MyBatis 封装、`platform-his`、业务仓之间的 jar。

## 2.1 命名

| 对象 | 规则 | 现名 |
| --- | --- | --- |
| 运行时服务 | 小写、中划线、用它拥有的能力。不带 `-service`，不叫 `his` | `clinical-record`、`nutritionist`、`consult-gateway`、`consult-identity`、`consult-registration`、`consult-payment`、`consult-benefit` |
| Maven 模块 | 有接口模块时用 `{服务}-api`、`{服务}-service`。已经发布的目录名不改 | `nutritionist-service`、`consult-identity-service` |
| 包 | `com.moonligh.{服务名去掉中划线}` | `com.moonligh.clinicalrecord`。平台仓历史包 `com.moonligh.consult` 保留 |
| 浏览器接口 | `/api/{服务}/{资源复数}`，资源用小写中划线 | `/api/nutrition/recommendations` |
| 内部接口 | `/internal/{资源复数}`。一个资源一个 `*Controller` | `/internal/facts`、`/internal/persons` |
| 类 | 控制器 `*Controller`，用例 `*Service`，端口 `*Store`，实现 `*StoreImpl`，语句 `*Mapper` | 不用 `*Api`、`Jdbc*`、`Sql*` 作为正式类名 |
| 配置 | 新业务用自己的服务名。平台鉴权键仍是 `consult.auth` | 临床数据仓库令牌用环境变量 `CLINICAL_RECORD_TOKEN` |
| 错误码 | 平台枚举里的数字，见第 6 节 | `3101`、`3102` |

## 3. 运行时和依赖

- JDK 21，Spring Boot 4.1.1。
- 业务工程 `import` `platform-bom`。平台模块和下面列出的三方版本不在业务仓再写一遍。
- MyBatis 使用官方 `mybatis-spring-boot-starter` 4.0.1，版本由 `platform-bom` 管理。
- 不使用 MyBatis-Plus，不自封装 `BaseMapper`，不抽公共 MyBatis 模块。
- 数据源写在各服务自己的配置里。MySQL 8 是事实源。Redis 只做可丢失缓存。

## 4. 持久化

- SQL 只放在 `src/main/resources/mapper/*.xml`。
- `mapper-locations` 为 `classpath:mapper/**/*.xml`，并打开 `map-underscore-to-camel-case`。
- Mapper 接口标注 `@Mapper`。启动类使用 `@MapperScan`，且 `annotationClass` 为 `Mapper.class`。
- 事务注解放在应用服务上。
- 类名使用 `*Mapper`、`*StoreImpl` 或 `*RepositoryImpl`。
- 集成测试可以用 `JdbcTemplate` 准备数据。正式代码不把语句写在 Java 里。

## 5. 接口返回

对浏览器和智能体的业务接口使用平台 `Result`。HTTP 状态保持 200，成败看 `code`：200 成功，其它为错误码。

临床数据仓库的内部接口同样返回 `Result`：

- 成功时 `code` 为 200，`data` 是快照或追加结果。
- 空列表表示没有这项事实。
- `code` 不是 200 表示拒绝或失败。调用方不得把这种响应当成「没有慢病」。

内部路径是 `/internal/**`，不暴露给浏览器。请求头 `X-Internal-Token`，配置项 `consult.auth.internal-token`。未配置时与其它服务一样使用默认令牌 `consult-internal`。生产环境用 `CLINICAL_RECORD_TOKEN` 覆盖。

## 6. 错误码

错误码定义在平台仓 `ErrorCode`。新号码先写入该枚举，再在业务仓使用。

| 号段 | 使用方 |
| --- | --- |
| `1xxx` | 通用 |
| `11xx～13xx` | 挂号 / 问诊 |
| `21xx～30xx` | 营养 |
| `31xx` | 临床数据仓库 |

临床数据仓库当前使用：

| 码 | 含义 |
| --- | --- |
| `3101` | 临床事实未接受。命令不合法，档案没有变化 |
| `3102` | 病情档案暂不可用。调用方停止依赖这份档案的动作，不改用本地旧病情 |

## 7. 一致性

- 一次命令里的多条事实在临床数据仓库的一个本地事务中提交，并出现在同一个新快照里。
- 同一个 `commandId` 再投递一次，返回第一次的结果，不追加第二套。
- 智能体和临床数据仓库之间不使用分布式事务。至少投递一次，靠 `commandId` 去重。
- 已经生成的配餐和已经发布的解读记下当时的 `snapshotVersion`。以后的新事实不改写它们。

## 8. 安全和日志

- 令牌只证明调用方是内部服务，不证明用户可以看这个患者。
- 写事实前核对账号拥有该 `patientId`。身份服务不可用时拒绝新的命令和查询。这一项在身份核对接入后生效。
- 日志可以写 `patientId`、`factId`、`snapshotVersion`、`commandId`、Trace。不写病情正文、指标值、姓名和证件号。

## 9. 重构时的完成标准

一个服务算对齐，当且仅当：

1. 构建导入 `platform-bom`，MyBatis 版本不在本仓重复声明。
2. 正式代码中的 SQL 都在本服务的 Mapper XML 里。
3. 启动类有带 `annotationClass` 的 `@MapperScan`。
4. 事务在应用服务上。
5. 对外和内部接口返回平台 `Result`，错误码来自平台 `ErrorCode`。
6. `/internal/**` 使用平台内部令牌过滤器，不另写一套比较逻辑。
7. 不保存别的服务拥有的主数据。病情只读临床数据仓库的快照。
